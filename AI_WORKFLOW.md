## Important prompts and instructions

- `AGENTS.md` — repository-wide hackathon constraints and working agreement.
- `HACKATHON_BRIEF.md` and `docs/PLAN.md` — the product brief and the task cards (T0-T1, A1-A13, B1-B14, X1-X2, S1-S6, W1-W6). Every card ends with a **starter prompt** that was given verbatim to a fresh Claude Code agent in its own git worktree (the issue bodies on GitHub). Common rules in every starter prompt: edit only the files of your card, commit after each small working step, never put an API key in the repo or the logs, append a row to this file, open a PR with a verified vs unverified list and stop — **agents never merge**; a human merges.
- [`scripts/pack/prompts/historian-v1.md`](scripts/pack/prompts/historian-v1.md) — the Historian persona prompt that drafted the stop stories from the cited sources only (no invented facts, every claim tied to a source in `sources.json`).
- [`scripts/pack/prompts/translate-v1.md`](scripts/pack/prompts/translate-v1.md) — the prompt for the Polish and Chinese machine translations of those stories.
- `docs/research/new-tours.md` — the research brief that produced the two extra courses (Scholars and Saints, Kazimierz).
- Product decisions given by the user in chat and quoted in the log rows below (for example "Eyes on the city, not the screen", "the app must not be hard-coded for Kraków", "we shouldn't NEED to download courses").

## Workflow

### Ideation and architecture

The team picked the idea (a screen-free audio walking tour) and the platform capabilities; Claude Code did the research around it: it read the challenge rules and the HarmonyOS docs through `devecocli docs`, probed the data endpoints from the venue network (`docs/RISKS.md`: Overpass was down, so places come from Wikidata), and ran spikes on the emulator before the architecture was fixed (the en-US system voice cannot be downloaded on the emulator, so the studio voice became the primary voice). It wrote `docs/ARCHITECTURE.md`, `docs/DESIGN.md`, `docs/PLAN.md` and `docs/SERVER.md`; the humans reviewed them and made the product calls (scope, no human story review, city-agnostic app, streaming, the wording of the UI).

### Implementation

Two people, each driving Claude Code (Opus 5.5): Person A in the desktop app, Person B in the VS Code extension. Each task card ran as its own agent in its own git worktree and branch; independent cards ran in parallel. The rule was pure logic first (`common/src/main/ets/core/**`, no Kit imports, unit-tested), Kit adapters second. Every agent finished with a PR listing what was verified and what was not; a human read the PR and merged it, resolving conflicts when two branches touched the same file. `AI_WORKFLOW.md` uses a union merge driver so both sides' rows survive.

### Testing and debugging

- Every change: `devecocli` arkts check, the unit tests (`scripts/test.sh`, 440 tests at the end, needed because `hvigorw test` exits 0 even when tests fail) and a full build.
- Behaviour on the emulator (Pura 90, HarmonyOS 6.1.1) through `devecocli run`, UI inspection (`ui layout`, `ui click`, screenshots) and structured hilog lines (`NARR_AUDIO`, `LOC`, `ev=START_TOUR`, `LANG_SWITCH`, ...). A replay integration test and a Demo walk smoke script (`scripts/smoke.sh`) gave repeatable evidence; later in the event the smoke script was run only on demand, and the humans tested by hand on the emulator.
- Server: `vitest` tests in `server/`, then a deploy on Render and live checks against `/healthz`, the signed catalog and `/v1/tts`.
- Bugs were diagnosed from logs and faults (`THREAD_BLOCK_6S`, error codes such as 13900015 EEXIST, HTTP 201 vs 200), not guessed; each fix was confirmed on the emulator.

## Unsuccessful approaches

- `devecocli emulator geolocation` (inject GPS location and heading from the CLI) fails with "Emulator scene control commands require Emulator 7.0 or later". The newest emulator available to us is 6.1.1.200, so location simulation has to come from the emulator UI or an in-app, clearly labelled demo source.

- Downloading the en-US system TTS voice (Laura, `person 8`) fails on the emulator; English is spoken by the studio voice, and the zh-CN system voice is only the last resort.
- Overpass (OSM) returned 504 from the venue network; places come from Wikidata SPARQL snapshots instead (`docs/RISKS.md` x1).
- Drawing the map from SVG `Path2D` strings drew only part of the base map; replaced by an incremental `moveTo`/`lineTo` build.
- Yielding between map slices with `setTimeout(step, 0)` still blocked the UI thread (`THREAD_BLOCK_6S`); a 4 ms delay fixed it.
- A Demo walk rule "hold anywhere the story is still playing" deadlocked the walk (the walker waited for a story that waited for an arrival); reverted to holds only at stops.
- The first Vercel deploy detected the Express server in `server/` and tried to build it; the static site config moved into `site/`.

## Known limitations

- Not tested on a physical phone before submission; everything was verified on the emulator, which cannot give real GPS, so walks are shown with the clearly labelled Demo walk.
- Story texts are AI-drafted from cited sources and were not reviewed by a human (a team decision); Polish and Chinese are machine translations. The ElevenLabs voice may mispronounce some Polish names.
- The built-in system voice (zh-CN voice reading English on the emulator) remains the last-resort fallback when a clip is missing and the server is unreachable.
- The submitted `.hap` is unsigned; a device needs DevEco auto-signing with the user's own Huawei ID.

## Lessons learned

- Small task cards with a starter prompt, one worktree per agent and "agents never merge" let several agents work in parallel without breaking `main`.
- Keep the pure logic free of Kit imports: it made 440 unit tests possible without a device and let the watch app reuse the same core through a HAR.
- Spike the platform before designing on it: the en-US voice download and `emulator geolocation` both failed on the emulator, and finding that early changed the architecture rather than the demo.
- Read the faults, not the symptoms: "the emulator is laggy" was a UI-thread block in our own map code, visible as `THREAD_BLOCK_6S` in hilog.
- On ArkTS, a `setTimeout(fn, 0)` loop does not yield to the UI; a real delay does.
- Never let a key reach the app: the ElevenLabs key lives only in the server's environment, and a pre-commit hook rejects key values and signing files.

## AI feature disclosure

AI is part of the product in one place: the narration voice.

- **Model or service:** ElevenLabs text-to-speech, `eleven_multilingual_v2`, premade voice "George". The story texts were drafted by Claude (Opus 5.5) from cited sources ([`historian-v1.md`](scripts/pack/prompts/historian-v1.md)); Polish and Chinese are machine translations ([`translate-v1.md`](scripts/pack/prompts/translate-v1.md)). No human reviewed the story texts (team decision). The cover photos are human-made Wikimedia Commons photos, credited in Settings › About.
- **Inference flow:** stop stories are rendered once at build time (`scripts/voice/render-elevenlabs.mjs`) and published with each course by the course server; the app downloads or streams them. Short dynamic lines (welcome, arrival, turn-by-turn with distances) are rendered at runtime by the course server's `POST /v1/tts` (`server/src/tts/`), which calls ElevenLabs only for a line whose sha256 is in the course's pre-published **allowed-lines set** (no free text), caches every result forever and enforces a daily character budget and a circuit breaker (`docs/SERVER.md` §2, §4). No AI model runs on the phone, and the app never calls ElevenLabs directly.
- **Data handling and privacy:** the app sends only the course id, the language and the line text, with an anonymous install token. No location, no account, no personal data. The ElevenLabs key lives only in the server's environment, never in the app, the repo or the logs (the server redacts the TTS text and tokens from its logs; the pre-commit hook rejects key values).
- **Failure and fallback behaviour:** a clip plays only if the sha256 of its exact text matches the manifest (same language and persona). Otherwise the app asks the server; any non-200 answer, a timeout or no network falls back to the built-in HarmonyOS voice (Core Speech Kit). A downloaded course works fully offline. Logged as `NARR_AUDIO src=prerendered|remote|remote_cache|tts|text reason=...` (plus `REMOTE_TTS result=... cache=hit|miss`).
- **Evaluation:** unit tests for the hash match, language and persona checks, story coverage and the voice plan (`ClipSelection.test.ets`, `TourController.test.ets`); the system lines golden-tested against the server's allowed set (`SystemLines.test.ets`); server tests for the allowed set, budget, breaker and single-flight. Listened to on the emulator in en, pl and zh. Known limitation: the AI voice may mispronounce some Polish names. Disclosed in Settings › About and in the presentation.
